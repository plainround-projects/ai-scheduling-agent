# SQL seed data, every row

## What it is

The seed files hold the sample data the databases start with: people and meetings, customers and orders, help-center pages. Each file is a list of `INSERT` statements. This note quotes every statement in full, so every row of sample data is visible.

## Why this repository uses it

The checks in the README (no double bookings, no refund above an order total, version numbers that add up) are run against this data. The data is generated by a script from a fixed seed (see the scripts note), written into SQL and committed, so the database a reader builds is the same one the author measured.

## How it works underneath

`make db` feeds each file to the database through the command-line client. An `INSERT INTO table (columns) VALUES (...), (...);` statement adds many rows at once; the values are matched to the columns by position. The database checks every row against the table's constraints (`NOT NULL`, `CHECK`, `REFERENCES`) as it is inserted, so a bad row stops the whole statement. The file is applied only when the table is empty, which keeps `make db` repeatable (see `make.md`).

## Mistakes people make

- **Editing the seed by hand.** It is generated; the script and its seed are the source.
- **Loading the seed twice.** Primary keys would collide; the Makefile loads it only into an empty table.
- **A value in the wrong column.** Values match columns by position; the column list in the statement is the guide.
